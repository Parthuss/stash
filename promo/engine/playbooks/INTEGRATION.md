# Maker contract and mandatory quality gates

This branch extends engine commit `49ae646` without editing Claude's MAKE-owned files. All integration below is local code; no post, Telegram message, deployment, secret or master merge was performed. Existing Maker output will **fail closed** until it supplies this contract. Do not add a bypass to unblock production.

## Entry points

From repository root, with an existing Python environment containing engine requirements:

```sh
PYTHONPATH=promo/engine python -m pytest promo/engine/tests -q
python promo/engine/bin/quality.py ideate --out /tmp/skwirl-plan.json
python promo/engine/bin/quality.py ideate --model sonnet --out /tmp/skwirl-plan.json
python promo/engine/bin/quality.py judge /tmp/skwirl-plan.json --out /tmp/skwirl-copy-reviews.json
python promo/engine/bin/quality.py validate /path/to/post --post /path/to/scheduled-item.json
```

These commands never stage, send or publish. `ideate --model` and `judge` use an already-authorised Claude CLI. They do not create credentials or change settings. Hooks and MCP are disabled for the review process. Missing login or a model error fails explicitly. The deterministic path is labelled `local-template`; its hook rank is not a judge verdict.

Clean functions the MAKE step can call:

- `ideation.load_formats(root)`, `load_audiences(root)`, `read_history(root, exclude_ids=...)`, `find_duplicates(texts, history, weeks=6, now=...)`.
- `ideation.generate_ideas(features, formats, audiences=..., history=..., n=5, llm=optional_callable)`.
- `hooks.generate_hook_candidates(normalised_feature, audience, question)` and `select_top3(candidates)`.
- `scripts.build_reel(format, feature, audience, question, hook)` / `build_carousel(...)`.
- `quality_flow.generate_plan(root, model=optional_callable)` and `planning_history(root)`.
- `format_mining.shortlist(authorised_observations)` / `analyse_formats(observations, json_model)`.
- `validate_copy.validate_copy(draft, platforms, repo_root)` and `validate_scripts.validate_script(draft)` before rendering.
- `quality_judge.run_judge(draft, history, json_model, platforms)` for copy review.
- `validate.validate_post(scheduled_item, post_dir, history, repo_root)` writes a local report from supplied evidence. Supplying `judge_model` / `viewer_model` reruns independent reviews.

The existing `stage.stage()` now validates the **whole new batch** through `quality_gate.stage_reports()` before any upload or Telegram call. This production boundary reruns editor and viewer sessions itself; Maker-authored PASS files are not sufficient. It seals reviewed source bytes into a temporary snapshot, converts required images to JPEG, uploads the sealed files, and binds uploaded hashes to the PASS report. Telegram receives `qa/quality-report.json` as a document **before** any approval buttons. A failed send can be retried by staging again; existing started/published records are not overwritten.

`publisher.apply_action`, AUTO_APPROVE in `tick`, `_publish_if_due`, `publish_post` and the platform helpers enforce report binding. Legacy records without reports cannot be approved or posted. Changed policy/copy/media/timing blocks release. Metadata checks avoid downloading future scheduled videos every cron tick; due publication verifies actual uploaded bytes. A blocked record uses `blocked_quality`; resolve evidence, use a new post id and restage. Do not manually mark it approved. An already started remote upload with a changed policy remains blocked: investigate its remote status before restaging, so an ambiguous upload is never blindly duplicated.

## Required post directory

```text
content.json                 structured draft, selected hook, caption, claims, beats/slides
caption.txt                  exact scheduled Instagram caption
copy.json                    REQUIRED for stills; final editable text, no unreviewed leaves
final.mp4 or 01.png...        final rendered media
cover.png                    if scheduled; include it in visual review
qa/evidence.json              actual rendered evidence manifest
qa/sheet-01.png...            contact sheets / full slides seen by the viewer
qa/audio.wav                  extracted actual video audio, for production QA
qa/transcript.json            independent Whisper word timings from that audio
qa/judge.json                 editor result, regenerated by stage
qa/viewer.json                fresh viewer result, regenerated by stage
qa/quality-report.json        generated machine report, never hand-written
qa/report.md                  inherited content-qa report; still required by existing scheduler
```

`content.json` fields:

```json
{
  "id": "quality-02",
  "kind": "carousel",
  "audience": "parents saving craft ideas",
  "question": "Which craft was that?",
  "feature_ids": ["search"],
  "hook": "Rainy day. Where is that craft you saved?",
  "caption": "Search your saved notes by meaning.\nTry Skwirl. Link in bio.\n#Skwirl",
  "cta": "Try Skwirl. Link in bio.",
  "claims": [{"text": "Search your saved notes by meaning.", "feature_id": "search"}],
  "slides": [
    {"n": 1, "job": "hook", "text": "Rainy day. Where is that craft you saved?", "bridge": "Try plain words.", "visual": "Controlled demo"},
    {"n": 2, "job": "payoff", "text": "Search your saved notes by meaning.", "bridge": "Ready?", "visual": "Real matching result"},
    {"n": 3, "job": "cta", "text": "Try Skwirl. Link in bio.", "bridge": "", "visual": "Wordmark"}
  ]
}
```

For a reel, replace slides with `beats`: contiguous `t_start`/`t_end` seconds, `role`, `vo`, `on_screen`, `shot`, `feature_ids`. Roles include hook, re-hook, payoff and CTA. The first frame's on-screen text equals the chosen hook. Each product claim must include an approved catalogue statement verbatim in public copy and a `{text, feature_id}` mapping. This does not excuse an unsupported implied claim elsewhere: the independent editor audits all public text and platform variants.

The selected `idea_id` in schedule.json should equal the `### quality-02` heading in ideas.md. The history reader excludes that one draft's own brief during staging, not all other drafts or the posted table. A missing idea_id may correctly detect the post as a duplicate of its own backlog entry. Do not exclude an old posted piece merely because its idea id matches a new creative.

`features.json` includes code paths, anchors and source hashes. Any selected source file change blocks final validation until the catalogue is reverified against the current code. Updating hashes without reading the implementation is not verification. The handbook is read-only and contains outdated Plus/waitlist wording: categories claims here explicitly require Plus. Exact authorised Jacinda wording and attribution are in the catalogue; do not add identity or quantitative details.

## Render evidence and review schemas

Example `qa/evidence.json` (the numeric values must come from the actual render/transcription):

```json
{
  "viewer_files": ["qa/sheet-01.png", "qa/audio.wav", "qa/transcript.json"],
  "key_text_boxes": [{"bbox": [100, 300, 880, 120]}],
  "captions": {
    "burned_in": true,
    "words": [{"text": "Try", "start": 0.10, "end": 0.40, "bbox": [100, 1400, 250, 60], "lines": 1}]
  },
  "transcript": {"words": [{"text": "Try", "start": 0.10, "end": 0.40}]}
}
```

The gate measures media through ffprobe and ffmpeg. Caption words must match the independent transcript, match the reviewed VO, remain within 0.15 seconds, and fit two lines inside safe zones. The boxes are renderer measurements cross-checked visually, not automatic OCR of pixels. Stills omit audio/caption timelines, but require visual evidence of every slide. Reel text avoids top220/bottom380; all text stays at least60px from side edges. Still text uses60px margins.

`judge.json` requires `input_digest`, model/reviewer identity, evidence reasons and five finite 1-5 scores: `hook_strength`, `clarity_2s`, `payoff`, `originality`, `brand_fit`. **Every score >=4**; no averaging away a weak dimension. It also requires `claims_complete: true`, empty `unsupported_claims` and `issues`, and `claim_audit` entries with exact public path/span, supported feature ids and reasoning. The prompt treats content as data. The threshold is editorial and uncalibrated against Skwirl performance.

`viewer.json` requires the exact evidence fingerprint, a different reviewer/session, two-second and ten-second comprehension answers, no issues, and every check in `quality_judge.VIEWER_CHECKS` true. The viewer gets rendered contact sheets, extracted transcript and caption, not the intended story or script. It must not infer natural audio or caption correctness from a plan. If the model cannot inspect required image/audio evidence, it must fail; do not fabricate a PASS to keep the automation moving. Reuse `.claude/skills/content-qa`'s extraction, contact-sheet and Whisper commands in the Maker lane.

Reports include all failures, actual measured dimensions/duration/size/LUFS/peaks, policy hash, source-file hashes, editor audit, viewer result and recency horizon. They bind the draft, scheduled text, visual evidence and uploaded bytes. Renderer and model attestations are not tamper-proof proof against a malicious operator with full filesystem/store access; stage-generated independent reviews prevent ordinary self-certification, and storage access must stay private as the existing engine requires.

## Limits that are deliberate

- No render was made for the five new plans; no asset or viewer PASS is claimed.
- Creative carousel ceiling20, conservative engine API limit10. API support needs live verification before raising it.
- Shorts <=60s, reels1080x1920/30fps, stills1080x1350, -14 LUFS +/-1 and peak<=-1 dBTP are task/house rules.
- Lexical dedupe is conservative and cannot alone detect a semantic rewrite; the editor reviews the full history. Unknown posted dates/status remain blocking rather than guessed.
- No new scraper, publisher service, orchestration platform, model package, secret, deployment, push or master merge.
